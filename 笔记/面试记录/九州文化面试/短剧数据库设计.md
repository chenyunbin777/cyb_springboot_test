# 设计思路
在编写时，我补充了合理的索引设计和通用字段（is_deleted软删除标记），并统一使用utf8mb4字符集以支持所有语言，这更符合海外App的需求。


字符集：所有表都使用了utf8mb4字符集，可以完美支持表情符号和各种小语种字符，这对海外App是必须的。

ID生成：user_id、drama_id、episode_id、product_id等主键建议使用雪花算法（Snowflake） 生成，而不是自增ID。这样既保证了全局唯一，也便于后续做分库分表。

软删除：所有表都包含了is_deleted字段，数据删除时只做标记，不物理删除，便于数据恢复和审计追溯。

索引策略：这里只建立了一些常规索引。上线后，你需要根据实际的慢查询日志来持续优化索引。

创建顺序：执行时，请按 1 → 2 → 3 → ... → 9 的顺序执行，以确保有外键依赖（如果有的话）不报错。本例中没有物理外键，所以顺序自由，但逻辑上建议按此顺序。

你可以把这些SQL直接在MySQL 5.7+或8.0的环境中执行。

# 一、用户服务 (User Service)

## 1. 用户主表 (users)
密码采用非对称加密MD5存储到数据库中，就算是sql数据被盗也不会透露对应的密码是什么！
登陆验证时：通过对比加密数据来判断，无法解密数据库中密码数据的

`
CREATE TABLE `users` (
  `user_id` bigint(20) NOT NULL COMMENT '用户ID，由分布式ID生成器生成',
  `username` varchar(64) NOT NULL DEFAULT '' COMMENT '用户名',
  `phone` varchar(20) DEFAULT NULL COMMENT '手机号（国际区号+号码）',
  `email` varchar(100) DEFAULT NULL COMMENT '邮箱',
  `password` varchar(255) NOT NULL DEFAULT '' COMMENT '登录密码（BCrypt加密）',
  `nickname` varchar(64) NOT NULL DEFAULT '' COMMENT '昵称',
  `avatar_url` varchar(255) DEFAULT '' COMMENT '头像URL',
  `status` tinyint(4) NOT NULL DEFAULT '1' COMMENT '用户状态：0-冻结，1-正常，2-注销',
  `last_login_ip` varchar(45) DEFAULT NULL COMMENT '最后登录IP',
  `last_login_time` datetime DEFAULT NULL COMMENT '最后登录时间',
  `is_deleted` tinyint(1) NOT NULL DEFAULT '0' COMMENT '逻辑删除标记：0-未删除，1-已删除',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`user_id`),
  UNIQUE KEY `uk_username` (`username`) USING BTREE,
  UNIQUE KEY `uk_phone` (`phone`) USING BTREE,
  UNIQUE KEY `uk_email` (`email`) USING BTREE,
  KEY `idx_status_created` (`status`, `created_at`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='用户主表';
`

## 3. 钻石流水表 (coin_transactions)

CREATE TABLE `coin_transactions` (

# 二、内容管理服务 (Content Management Service)

## 4. 短剧主表 (dramas)
短剧主要的信息：包括 短剧名、类目、导演、演员、状态（上架、下架）、连载中/已完结，总播放量、总收藏、总点赞、总评论数（评论数据需要单独一个表）

评论表：每一个剧集对应的所有评论（这个数量应该会很大，可以考虑**分库分表**）
剧评表：就像是豆瓣点评一样（用户名、星数、评论、评论点赞数等）

`
CREATE TABLE `dramas` (
  `drama_id` bigint(20) NOT NULL COMMENT '短剧ID',
  `title` varchar(255) NOT NULL DEFAULT '' COMMENT '短剧标题',
  `cover_url` varchar(255) DEFAULT '' COMMENT '封面图URL',
  `description` text COMMENT '短剧简介',
  `category` varchar(64) DEFAULT '' COMMENT '分类（如：爱情、喜剧）',
  `tags` varchar(255) DEFAULT '' COMMENT '标签（逗号分隔）',
  `director` varchar(64) DEFAULT '' COMMENT '导演',
  `cast` varchar(255) DEFAULT '' COMMENT '主演（逗号分隔）',
  `status` tinyint(4) NOT NULL DEFAULT '0' COMMENT '连载状态：0-已完结，1-连载中',
  `publish_status` tinyint(4) NOT NULL DEFAULT '0' COMMENT '上架状态：0-下架，1-已上架',
  `is_recommended` tinyint(1) NOT NULL DEFAULT '0' COMMENT '是否推荐：0-否，1-是',
  `sort_order` int(11) NOT NULL DEFAULT '0' COMMENT '排序值（值越大越靠前）',
  `view_count` bigint(20) NOT NULL DEFAULT '0' COMMENT '总播放量',
  `like_count` bigint(20) NOT NULL DEFAULT '0' COMMENT '总点赞数',
  `favorite_count` bigint(20) NOT NULL DEFAULT '0' COMMENT '总收藏数',
  `rating` decimal(2,1) DEFAULT NULL COMMENT '评分（如：8.5）',
  `publish_date` date DEFAULT NULL COMMENT '上架日期',
  `is_deleted` tinyint(1) NOT NULL DEFAULT '0' COMMENT '逻辑删除标记',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`drama_id`),
  KEY `idx_publish_status_sort` (`publish_status`, `sort_order`) USING BTREE,
  KEY `idx_category_status` (`category`, `publish_status`) USING BTREE,
  KEY `idx_is_recommended` (`is_recommended`, `publish_status`) USING BTREE,
  KEY `idx_view_count` (`view_count`) USING BTREE,
  FULLTEXT KEY `ft_title_description` (`title`, `description`) WITH PARSER ngram
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='短剧主表';

`

## 5. 剧集表 (episodes)
短剧每一个剧集的详情信息：标题、视频链接、剧集描述、剧集评论数、剧集点赞数、剧集分享数、排序、**访问权限（重点字段）**

解锁设计思路：用户每次看视频的时候，需要【请求后端】判断【访问权限】！   设计一个 episodes/auth/info 接口
1、免费直接看
2、VIP需要判断用户状态
3、钻石付费：需要用户付费后观看
4、广告解锁时，后端要返回广告url与敢看广告时常等信息！

如果可以免费试看的话，可以试看到多少秒

`
CREATE TABLE `episodes` (
  `episode_id` bigint(20) NOT NULL COMMENT '剧集ID',
  `drama_id` bigint(20) NOT NULL COMMENT '所属短剧ID',
  `episode_number` int(11) NOT NULL COMMENT '集数（第几集）',
  `title` varchar(255) DEFAULT '' COMMENT '本集标题（可选）',
  `video_url` varchar(255) NOT NULL DEFAULT '' COMMENT '视频文件URL（指向CDN）',
  `cover_url` varchar(255) DEFAULT '' COMMENT '本集封面（可选）',
  `duration` int(11) NOT NULL DEFAULT '0' COMMENT '视频时长（秒）',
  `file_size` bigint(20) NOT NULL DEFAULT '0' COMMENT '视频文件大小（字节）',
  `access_type` tinyint(4) NOT NULL DEFAULT '0' COMMENT '访问权限：0-免费，1-VIP，2-钻石付费，3-广告解锁',
  `price_coins` int(11) NOT NULL DEFAULT '0' COMMENT '解锁所需钻石数（access_type=2时必填）',
  `is_free_preview` tinyint(1) NOT NULL DEFAULT '0' COMMENT '是否免费试看：0-否，1-是',
  `status` tinyint(4) NOT NULL DEFAULT '0' COMMENT '剧集状态：0-下架，1-已上架',
  `sort_order` int(11) NOT NULL DEFAULT '0' COMMENT '排序（用于控制播放顺序）',
  `is_deleted` tinyint(1) NOT NULL DEFAULT '0' COMMENT '逻辑删除标记',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`episode_id`),
  UNIQUE KEY `uk_drama_episode` (`drama_id`, `episode_number`) USING BTREE,
  KEY `idx_drama_id_sort` (`drama_id`, `sort_order`) USING BTREE,
  KEY `idx_status_access` (`status`, `access_type`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='剧集表';
`

## 6. 短剧多语言表 (drama_i18n) - 海外扩展
内容多语言：为了适应海外市场，可以将短剧主表(dramas)中需要翻译的字段（如title, description, tags）抽离出来，设计一个独立的多语言内容表(drama_i18n)，通过language_code（如en-US, ja-JP）来区分。
`
CREATE TABLE `drama_i18n` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '自增主键',
  `drama_id` bigint(20) NOT NULL COMMENT '短剧ID',
  `language_code` varchar(10) NOT NULL COMMENT '语言代码（如：en-US，ja-JP）',
  `title` varchar(255) NOT NULL DEFAULT '' COMMENT '本地化标题',
  `description` text COMMENT '本地化简介',
  `tags` varchar(255) DEFAULT '' COMMENT '本地化标签',
  `is_deleted` tinyint(1) NOT NULL DEFAULT '0' COMMENT '逻辑删除标记',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_drama_language` (`drama_id`, `language_code`) USING BTREE
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_unicode_ci COMMENT='短剧多语言内容表';
`
