应用内购买（In-App Purchase，简称IAP）是Apple App Store和Google Play平台上，数字商品与服务的核心变现方式。两大平台的IAP机制、费用和政策既有相似之处，也存在关键差异。

二 Apple Store

Apple的IAP研发主要围绕 StoreKit 框架展开，目前推荐使用 StoreKit 2。

1. 客户端集成 (StoreKit)
核心框架：使用 StoreKit 框架与App Store服务器交互，处理产品请求和购买流程。

获取产品信息：从App Store Connect获取可用的产品列表及其价格等信息。

发起购买：调用购买接口，系统会弹出原生支付界面让用户确认。

处理交易：监听交易状态更新（Transaction.updates），在交易成功后获取交易信息。

获取收据 (Receipt)：购买成功后，从App的Bundle中获取收据数据，并进行Base64编码，然后发送给你的服务器。强烈建议所有验证在服务端完成，不要在客户端做任何有安全依赖的校验。

2. 服务端验证 (Receipt Validation)
服务端验证是确保交易真实性的关键，Apple提供了新旧两种方式：

方式一：App Store Server API (推荐，StoreKit 2)

这是Apple官方推荐的新方式。

你的服务器需要使用App Store Connect API密钥（而不是共享密钥）来生成JSON Web Token (JWT)，以调用Apple的API。

主要接口是 GET https://api.storekit.itunes.apple.com/inApps/v1/transactions/{transactionId}，通过transactionId直接获取交易详情。

方式二：旧式收据验证 (StoreKit 1)

使用旧的 verifyReceipt 端点。

服务器将客户端传来的Base64收据数据，连同共享密钥 (Shared Secret) 一起，发送到Apple的验证服务器。

注意：需要特别处理沙盒环境（状态码21007）和生产环境（状态码0）的切换。


三  Google (Android) IAP 研发要点
1. 客户端集成 (Play Billing Library)
核心库：集成 Google Play Billing Library。
初始化：建立与Google Play的连接，初始化 BillingClient 实例。
查询产品：查询你在Google Play Console配置的商品信息。
发起购买：启动购买流程。
处理购买结果：在购买回调中，获取购买令牌 (Purchase Token)。这是一个全局唯一的字符串，应作为你服务端数据库中的主键。

2. 服务端验证 (Purchase Token Validation)
客户端将获取到的 purchaseToken 发送给你的服务器。
你的服务器需要使用服务账号并配置好权限，通过 Google Play Developer API 来验证这个令牌。
主要接口是 Purchases.products:get 或 Purchases.subscriptionsv2:get。
验证通过后，服务器需要调用API来确认 (Acknowledge) 此次购买，对于消耗品，还需要调用消耗 (Consume) 接口。只有确认后，交易才算最终完成。
3. 测试环境 (Testing)
Google Play提供了封闭式测试 (Closed Testing) 和内部测试 (Internal Testing) 轨道。

你需要在 Google Play Console 中将测试人员的Google账号添加到许可测试列表中。

测试人员通过测试链接安装应用并进行购买，过程中不会产生真实扣费。

Google官方也提供了 Play Billing Lab 工具，帮助开发者验证商品和订阅配置是否正确






安全最佳实践
永远在服务端验证：这是最核心的原则，客户端的所有数据都不可信。
防止重放攻击：在服务端，务必检查接收到的transactionId(Apple)或purchaseToken(Google)是否已经被使用过。
管理好密钥：妥善保管Apple的App Store Connect API密钥或共享密钥，以及Google Play的服务账号JSON密钥，切勿提交到代码仓库。
正确处理消耗品：对于Google Play，必须在服务端确认并消耗（Consume）商品后，用户才能再次购买。
